# QuizForge Web 首次目录加载设计

状态：方案范围已获用户同意；本文等待设计审阅。尚未修改产品代码。

## 目标与证据

用户希望首次进入尽快看到题库列表，并缩短打开题库的等待；同时保留坏题库提示、编辑与发布校验以及文件变更检测。

上一轮使用当前运行 JAR、Java 25.0.4.1、17 个题库和 9 个开发拓展的隔离新服务及新页面，目录请求为 18,678.2 ms，列表 DOM 完成为导航后 19,465.3 ms，首题就绪为 25,684.9 ms。这是单次基线，不能视为稳定统计。Java 21 下 7.5 秒的函数计时不能作为整页指标。

本次改动涵盖轻量目录、单集合加载、后台校验、成功校验持久缓存和资源导入复用。保留自动打开首个题库的行为。首题所需的全库答题状态计算及描述/首题接口合并暂不纳入本次实现；完成本次整页测量后，再根据剩余耗时决定是否改动。

列表 DOM 在相同数据与环境下达到导航后 2 秒以内是优化目标，不是预先保证；验收必须报告真实测量值。

## 当前问题

- `Library.catalog()` 在 `Library` 锁内调用 `refresh()`，进行全库准备、规则校验、资源导入和大纲生成。
- `collection()`、`page()` 和开发描述接口也依赖全库刷新，不能只改浏览器的目录请求。
- 浏览器 `refreshCatalog()` 等待 `/api/catalog`，之后才渲染列表并打开首题。
- 成功规则校验仅缓存在内存，服务重启后丢失。
- 多个开发题库引用相同扩展时，刷新中重复导入扩展图片。

## 方案选择

采用轻量目录加按需校验。它能改善没有任何缓存的首次进入，并将耗时从全库转移到实际打开的集合。

仅增加磁盘缓存只能改善后续重启，无法解决第一次进入。仅并行执行原全库扫描仍要求列表等待全部结果，还会增加规则进程竞争。这两项都不能单独替代目录与加载职责拆分。

## 接口与展示

新增 `GET /api/library/index`，沿用目录响应中的 `banks`、`extensions`、`groups`、`canManage` 及行的 `id`、`kind`、名称、描述、路径、分组、题目数量等字段。接口执行相同的读取鉴权和目录路径约束。

新增字段：

- `indexRevision`：当前目录元数据快照的内容标识；用于取消过期后台任务与浏览器轮询结果。
- 每行 `validationStatus`：`pending`、`checking`、`ready`、`error`。
- 只有当前内容已完成完整加载时才返回原语义的 `contentRevision`。元数据标识不冒充完整内容标识。
- 错误行保留现有 `error` 表达方式。开发模式允许的规则未实现或拒绝等情况仍按既有容错处理；`ready` 表示按相应运行模式可加载，不表示开发题库已经具备正式评分能力。

轻量扫描只读取普通目录、受限大小的题库 JSON、manifest 和必要的开发声明，统计题目数量并检查元数据基本形状与引用身份。不得启动 Node，不导入图片，不生成完整大纲，不读取所有页面及 SDK 内容。无法读取或元数据非法的行直接为 `error`；尚未检查的规则、Schema、页面和资源问题不得提前宣称通过。

保留 `/api/catalog` 的完整校验契约及响应。导入候选库继续使用完整校验；目录管理、发布、导出和编辑的现有校验与锁定保证必须保留。旧接口与新接口共用加载器，避免维护两套校验规则。

前端首次与手动刷新使用轻量接口。待校验/正在校验行显示明确状态并允许点击触发优先加载；错误行保留现有错误提示。列表渲染完成后启动自动首库加载，随后开始后台校验。

存在待完成校验时，页面可见期间每 2 秒更新一次轻量目录；完成、切换认证会话或卸载页面后停止，页面隐藏时暂停。轮询不重启同一任务，不清空题目/页面缓存，不激活题库，不覆盖编辑输入；只接收当前刷新代次的响应。

目录管理返回的完整目录仍可使用；后续轻量响应缺少 `contentRevision` 不得被解释为内容未变化或内容已变化。打开集合使用经验证的真实修订标识进行题目、页面及编辑缓存判断。

## 加载与后台任务

将 `Library` 的职责拆成三个内部边界：目录元数据快照、指定集合的完整加载、校验任务协调。现有宿主准备、`RuleBatches`、大纲生成和错误包装作为唯一完整加载实现。

`collection(kind,id)` 只加载目标集合及所用扩展/SDK/图片。`page()`、开发描述和开发题库接口只加载相应扩展及必要集合；禁止这些路径回落到全库 `refresh()`。正式扩展的示例校验仍是扩展可用性的前提，但不得因此加载无关扩展或无关题库。

相同 ID 的多个候选按原扫描顺序检查，只校验为确定该 ID 归属所需的候选；保留“首个成功集合占用 ID，前面的坏集合不占用 ID”的行为。不同题库的相同题目 ID 不合并大纲。开发 UI 模式与普通开发模式继续使用各自的既有加载路径。

后台只处理尚未完成的集合。最多运行一个后台集合校验和一个前台集合校验，遵守现有 RuleEngine 进程限制；同一内容身份共用一个进行中的任务。前台优先于尚未开始的后台任务，正在执行的相同集合可复用结果。

目录锁仅用于获取任务、快照及提交结果。文件读取、资源导入和 Node 调用均在锁外完成；不得以后台线程调用原有同步 `refresh()` 代替本次拆分。完整目录接口也不得在持有全局锁时等待所有任务。

发布结果前重新确认目标集合与依赖的源版本、开发开关和目录代次。变更期间的旧结果丢弃，前台重新获取最新内容；持续变化无法获得稳定快照时返回明确冲突而不是返回旧成功结果。删除集合、关闭开发模式或关闭服务会移除未启动任务。执行器随服务关闭，不遗留线程或 Node 进程。

前台写入、发布与管理仍使用既有串行写入和冲突检查；禁止把未完成校验的元数据行构造成可写的 `Collection`。

## 成功校验持久缓存

仅复用规则校验成功结果和相应大纲结果，不缓存答题分数、答案、历史或编辑草稿。宿主结构/引用检查与资源可用性检查仍在加载时执行；规则结果中包含的 Schema 校验只在完整内容身份及校验环境完全相同的情况下复用。

缓存键包含完整题库内容、实际扩展身份/版本/内容指纹、依赖解析结果、开发运行模式、宿主校验协议版本、规则运行器内容指纹、实际 Node 版本及执行文件身份、规则依赖版本及实际代码指纹。环境指纹在启动时计算并在相关文件变化后重建。不得只使用题库 ID、路径、大小或修改时间判断缓存命中。

正式成功与按既有开发容错完成的结果分开标记；开发容错结果不写入正式成功缓存。规则超时、异常和无效结果不能写成成功记录。

缓存位于产品 `.state/validation-cache/v1/`，单条上限 2 MiB，总量上限 32 MiB，最多 2,048 条。超过上限的结果保留内存复用并放弃持久化。采用同目录临时文件与原子替换；读取损坏、未知版本、路径不安全或身份不匹配时忽略并重新校验。缓存写入失败不影响正确加载。淘汰仅涉及该命名空间内的缓存文件，不处理用户答案和资源文件。

服务重启仍重新进行轻量扫描；已选集合核实完整内容身份后才复用缓存。外部修改、编辑、导入、发布、移动及 SDK/runner 更新必须失效相应加载结果，不依赖页面轮询才能发现。

## 图片资源复用

图片首次按需加载时导入；同一 ResourceStore、扩展实际目录和资源内容身份共用导入任务。相同扩展被多个题库使用时只导入一次。正式状态与开发资源状态的导入不能互相冒充完成。

保留现有类型、大小、路径及哈希校验。图片新增、修改、删除或内容地址目标丢失时重新检查/导入。不得只用扩展 ID 或一次导入成功布尔值永久跳过检查。历史快照使用的图片仍遵守现有保留契约。

## 代码范围与兼容

主要涉及 `Library.java`、新增目录索引/加载任务/校验缓存内部类、`QuizForgeServer.java`、`app.js`、`views/library-view.js` 和相关文档及测试。资源导入复用可由加载器协调，避免给 ResourceStore 添加题库职责。

保持题库格式、扩展 API、规则 VM 的原集合分块重置边界、Schema及规则超时、沙箱、开发容错、题目/状态指纹与历史快照语义。导入/编辑/发布不减少校验。用户已有源文件、题库、答案和配置不迁移、不清理；不更换 Java、不安装依赖、不重启当前实际服务。

## 验证与交付条件

针对性回归必须证明：

1. 冷轻量目录的 Node 调用为零，资源导入为零；合法行显示待校验，非法元数据行独立报错。
2. 打开集合不校验无关集合；包括正式、开发、混合题型、UI 模式及扩展示例路径。
3. 慢后台规则正在运行时，目录及另一个目标集合可独立前进；相同内容请求共用任务且异常不会卡死后续请求。
4. 校验中修改/删除文件、关闭开发模式或切换刷新代次，旧结果不发布；修复坏库后可重新加载。
5. 重启可复用成功规则结果；题库/规则/Schema/依赖/runner变更使缓存失效；损坏或不可写缓存不影响正确性。
6. 重复题库 ID、跨库重复题目 ID、大纲状态、分块 VM 隔离、编辑冲突、导入/发布失败保留原行为。
7. 同一扩展资源跨库复用，图片变化后更新；前端状态轮询不清空编辑输入、不触发重复打开、不接受过期响应。

复用上一轮隔离基线的数据快照及 Java 25.0.4.1，使用新服务副本和新浏览器页面，测量至少三次独立冷启动以及带持久缓存的重启。依次记录轻量目录请求、列表 DOM 完成、目标集合校验、首题就绪和后台完成；报告中位数、范围和每次原始结果。后台浏览器帧回调不能标成屏幕实际绘制时间。

性能测量期间不并行运行重型测试，不复制凭据或用户答案；临时服务仅停止本次创建的准确进程。若列表达到目标但首题仍慢，明确报告剩余阶段耗时，不宣称整体问题全部解决。运行针对性 Java 与前端回归及必要兼容检查，记录验证边界。

## 设计自检

轻量与完整目录分离，现有完整接口保留；所有可写集合仍来自唯一完整加载器。后台工作不占全局锁，过期结果不提交；成功缓存不缓存错误或替代当前文件检查。性能目标与真实证据分开。剩余首题状态计算的优化范围已明确，本文不存在待定接口或默认降级校验路径。

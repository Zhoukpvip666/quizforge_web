## 2. 答题区最终产品行为

### 一个框、一个答案

- 答题区是有明确边框的正式答案范围，普通文字、图片与手写都放在同一逻辑平面。
- 默认可用普通文本框打字；不是再添加一个富文本答题区，也没有第二套独立手写答案。
- 草稿模式使用宿主唯一的白板、画笔、压力平滑、橡皮、撤销／重做与选择操作，不在框内重复提供画笔工具栏。
- 手写进入框内的部分作为正式答案，切回练习模式仍显示；框外保留为普通草稿。
- 输入命中层与可见笔迹分离。输入文字时不能通过抬高白色文本框把原笔迹遮住。
- 说明、标题、拍照／上传按钮、图片选框和删除确认都在答案范围之外，或在出图时排除。输入框没有会被评分误认的 placeholder／默认答案。

### 尺寸、跨设备与滚动

- 采用固定逻辑宽度，默认 760；手机、平板、电脑整体等比显示，文字、图片、笔迹不因窄屏重新排版。
- 浏览器百分比缩放、DPR、窗口变化、侧栏开合都要重新校准屏幕坐标与逻辑坐标，不能重写已存笔迹来“适配”新窗口。
- 编辑器设置的是默认高度。输入长文字、放入图片或框内新笔迹靠近底部时，按组件规则向下增长；删除内容不自动缩短。
- 不用文本框内部滚动隐藏答案，页面整体滚动。超过可用尺寸限制时保留输入并报告错误。
- 范围增长或题卡位置变化时，锚点、归属笔迹、下方范围和撤销记录需要同步；不能把原本框外的草稿误吸收为答案。

### 图片操作

- 显式开启 `allowImages:true` 后支持拍照、选择图片和粘贴图片；未适配的旧拓展不自动开启。
- 大图按原稿宽度等比放入。入口接受上限 20 MiB／4000 万像素，处理为最长边不超过 2560、资源不超过 4 MiB；单区至多 8 张。完整限制见答题区参考文档。
- 双击／双触图片选中，拖动图片移动，拖动四角等比缩放；点其他位置或 Esc 结束。
- 选中图片下方出现 ×，删除须确认。没有常驻图片调整栏或尺寸滑杆。
- 草稿模式下双击选图不能留下两个笔点，也不能擦掉原有笔迹；连续书写仍走宿主白板。

## 3. 保存、判分、AI 与历史

1. 拓展将组件返回的答题区文档放进自己的 answer，沿用原保存／提交接口。主／小题及区域 ID 保持稳定，不根据数组位置重新生成。
2. 普通草稿保存保留文字、图片引用、笔迹和锚点，不为每笔生成评分图片。
3. 单题提交、完成练习统一提交、考试交卷时，宿主按本次已保存答案版本检查并生成完整逻辑范围的结果。
4. 只有文字时，AI 接收 `text`。只要含图片或笔迹，AI 接收该区域的一张合成 PNG，图中已经包含区域内全部文字、图片与笔迹，不再重复发送同一区域的文本。
5. 合成顺序为白底 → 图片 → 文字 → 笔迹。包含屏幕下方尚未滚动看到的内容，排除框外草稿及任何操作控件。
6. 宿主移除客户端提供的旧 `snapshot`，重新生成可信图片资源引用，再交给拓展校验／评分。纯前端的任意截图不能直接被当作可信提交结果。
7. 图片上传、解码、组件状态同步和答案保存均纳入 flush。失败不能忽略图片、裁掉答案、写入部分结果或宣称提交成功。
8. 有作答但待人工／AI 判分时保持 `gradingStatus:"pending",score:null,correct:null`；不自动写成 0 分或错误状态。
9. 冻结历史保存当时的答案、资源引用、组件与页面，优先显示当时提交图。旧历史不按新组件重算，旧组件／模型版本不覆盖或删除。
10. `features.history:false` 继续使用原临时会话语义；本轮不新增隐式长期存储。

拓展示例的长期保存策略仍按原行为，本轮未调整，留待后续单独处理。已有未完成练习的恢复也应纳入两端升级验收；不能仅凭旧接口未变，就认定任意题库／拓展结构升级都能恢复活跃练习。本轮没有完成 Hub／Android 的跨版本迁移实测。

答案 Schema 采用该能力时应允许 `text`、`images`、`inkSource`、`anchor` 和宿主生成的 `snapshot` 等适用字段；`prepareAiGrading` 也须识别图片。字段与限额直接按 [ANSWER_AREAS](../reference/ANSWER_AREAS.md) 实现，不能仅在 UI 插入组件却保留不兼容的校验器。

## 4. 本轮一并修复的缺口

- **启动模块 404 导致列表空白**：浏览器新模块依赖共享模型与笔刷，静态服务必须提供对应路径；仅拷贝 app.js 不够。
- **ResizeObserver 循环通知**：合并尺寸测量和更新，避免无变化时反复写入尺寸；这类浏览器通知不应被桥接误判为题型业务失败。
- **浏览器缩放导致笔迹偏移**：统一 CSS、DPR、宿主相机、iframe 和答题区坐标换算，并重校准已有区域。
- **输入层覆盖笔迹**：通过独立透明命中层处理输入，可见内容继续由共享白板显示。
- **图片解码未完成即出图**：提交前等待资源解码完成；解码或图片完整性失败时保留答案并拒绝成功提交。
- **图片预览影响持久内容**：拖动预览不提前保存几何变化，取消恢复原位置；控件不进入评分图。
- **手机非全屏书写／框选变成大片遮罩**：窄屏练习 CSS 隐藏白板，旧代码将零尺寸布局当作一个像素，进入草稿时未重测，而观察的父容器不一定发生尺寸变化。现在进入草稿后及每次绘制前校准实际位图尺寸；隐藏时保留最后有效尺寸，不修改已保存笔迹／相机。用户随后反馈手机复测“正常了”；记录为本次手机场景通过，不外推为其他设备或浏览器均已验收。

共享前端保留这些依赖关系；平台改写实现时也要保留同等行为。

## 5. 随后确认的最终规则

### 获取题库直接进入广场

- `core/web/index.html` 的“获取题库”改为 `https://quizforge.treenewbee.cloud/manage/#library`，在新标签页直接打开题库广场，原作答页面保留，不经过网盘临时首页。
- Hub 会话已收到移除临时网盘首页的需求，根入口应恢复广场并保持 `/manage/` 兼容；Web 链接修改完成不代表线上临时页已移除。Android 若有独立入口，也应指向直接可用的题库广场。

### 移除草稿手动截图

- 移除草稿／历史工具栏的区域截图、C 快捷键、预览、PNG 下载与图片复制，删除 `core/web/draft/whiteboard-capture.js` 及对应专用测试；`app.js` 不再传 `onCapture`。
- 保留矩形框选笔迹、复制／移动／删除笔迹及撤销。此处“复制”指笔迹复制，不是截图复制。
- 答题区提交时的可信整区 PNG 与 AI 图片评分完全保留；`frame-capture.js` 仍承担答题区布局／交互桥接，不要一起删掉。

### 删除题库保留拓展

- 删除单题库或整个题库分组，只把所选题库移到应用回收目录，保留拓展和拓展分组。
- 取消为“连带清理拓展”读取全库内容、比较引用及移动拓展的流程。旧 `bankRemovalPlan` 已移除。
- 保留原目录检查、回收收据、失败回滚、作答与冻结历史；显式删除拓展仍保留引用保护。
- Web 管理响应为兼容保留 `removedExtensionGroups:[]`、`retainedExtensionGroups:[]`，不枚举保留组，不再返回依赖清理警告。
- 自动清理无用拓展留待后续单独功能，不在本次同步中顺带实现。
- 这是删除题库／题库分组的规则；此前实测的全库检查不是删除单道题目的流程。

### 单题编辑，必须先保存或取消

| 用户操作 | 最终行为 |
| --- | --- |
| 未改内容或撤销回原内容，切题／切库 | 直接切换并退出编辑 |
| 有修改，尝试切题／切库、历史／汇总或目录操作 | 弹窗阻止离开，只提供“返回编辑”；必须先保存或取消 |
| 保存本题 | 仅校验并保存当前题；成功退出，失败保留原输入 |
| 取消编辑 | 有修改时确认放弃当前题；取消确认继续编辑 |
| 刷新／关闭网页 | 未保存的作者编辑丢弃，再次读取已保存的原题 |
| 正式保存请求尚未完成 | 保留离页提醒，不把进行中的保存当作未开始的编辑 |

- 取消编辑草稿定时暂存、切题挂起与刷新恢复。当前 Web 不再调用 editor-drafts；旧存储／接口保留供其他兼容客户端使用，不自动删除旧文件。
- 一次只保留当前题编辑，顶部为“本题未修改／本题修改未保存”，按钮为“保存本题／取消编辑”。
- 取消上一轮“多题未保存列表、跨题跳转、题库计数、大纲圆点、保存本题库全部修改”。该方案虽然有历史测试记录，已被用户明确替代，勿同步成最终功能。
- 本条仅改变题目作者编辑。普通用户作答、草稿笔迹与图片的自动保存继续保留。
- 原 QF.editor.register 接口不变。取消损坏编辑器的操作也应可用，不能被失败的 flush 永远锁住。

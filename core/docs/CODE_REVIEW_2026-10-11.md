## 性能与文件结构

将宿主中的展示和恢复职责拆开，生命周期切换继续由 `app.js` 协调：

```text
core/web/
  app.js                     宿主流程、题卡生命周期及模块装配
  views/
    library-view.js          列表展示与操作回调
    outline-view.js          大纲展示、状态签名及 DOM 复用
  save-recovery.js            保存重试与读取已保存状态

core/src/main/java/io/quizforge/web/
  ExamSessions.java           考试编排、冻结记录和持久化
  TemporaryExamSessions.java 页面归属、容量、闲置和运行时释放

core/test/fixtures/
  legacy-extensions/          固定的旧版本拓展测试数据
  legacy-banks/               固定的旧演示题库
```

大纲按标签、题型、当前题/小题、提交分数及小题状态判断变化。仅答案文字、revision 或笔迹变化时保留 DOM 和键盘焦点；提交、标签和导航变化时仍更新。固定的 Node + JSDOM 合成场景包含 500 道题、30 次仅白板状态更新：原实现重建 30 次，约 2271 ms；新实现重建 0 次，约 14 ms。该数据用于证明消除冗余 DOM 工作，不能作为实际浏览器速度提升比例。

测试不再依赖用户当前安装的单选 1.0.0、简答 1.3.0 及两个演示题库。31 个文件从提交 `9a59e346b1ffd188358ed9e3b1919aed7568d388` 按原字节恢复到测试目录，来源和数量见 `test/fixtures/README.md`。产品目录中的原有删除保持不变。

完整回归还暴露出两处旧测试期待正式样例不可编辑，与当前契约及已有样例编辑测试相冲突。本轮保持现有受控编辑权限，改为验证非法编辑器路径拒绝、跨集合版本冲突及题目/状态字节不变。简答迁移测试补齐当前富文本服务所需的 1.1.3；新增过期测试夹具补齐规则契约必需的 `feedback`，未放宽业务断言或超时。

`CORE_SOURCE.md`、`EXAM_MODE.md` 和 `server/README.md` 已同步上述模块与边界。本轮没有按文件行数机械拆分状态事务；题卡替换、持久化和失效检查仍保持在可以审查的完整流程内。

## 后续性能工作

1. **整卷交卷事务，优先级 P2。** `ExamSessions.java:245` 在考试全局 monitor 中逐题调用 `StateStore.act`。首次提交即冻结整卷历史，逐题交卷会反复复制、序列化及原子写入整卷文档，还包含嵌套的线性题目查找；题量增长会放大成本，并延迟其他考试请求及到期检查。尚未做交卷基准，不对总耗时给出复杂度或速度结论。本轮没有改变这个提交协议。建议先用 100/500/1000 道已保存题测量交卷时间、状态写入次数和并发查询延迟，再设计带持久锁与崩溃恢复的批量事务；不能仅移除同步保护。
2. **暖读取目录扫描。** `Library.java:473` 的变更检查仍会遍历目录、读取声明及资源时间戳。建议先测量真实目录下 stamp/题目请求的延迟，再设计可失效的变更索引，保留外部修改检测和内容签名保护。
3. **题目 ID 索引。** `Library.java:57` 的集合题目查找为线性遍历。可在集合加载时建立不可变索引，同时验证重复 ID 和冻结历史兼容性；尚未修改或给出速度结论。

Java 修改需要重新打包并重启服务后才应用到现有运行实例。浏览器模块修改需要刷新页面；刷新前应完成当前输入的保存。

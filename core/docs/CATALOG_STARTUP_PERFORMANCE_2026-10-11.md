# 题库目录首屏优化与验证记录（2026-10-11）

## 本次改动

首页先读取 `/api/library/index` 元数据并显示列表，用户所选集合在独立前台通道完成校验。其余集合在后台逐个校验；列表显示 `pending`、`checking`、`ready`、`error`，可见时每 2 秒更新，全部达到终态后停止轮询。旧 `/api/catalog` 仍提供完整校验后的目录。

校验流程提取到 `CollectionValidation`，索引、指定集合加载、任务协调、资源复用、成功缓存分别位于 `LibraryIndex`、`ScopedLibraryLoader`、`LibraryLoadCoordinator`、`LibraryResourceImports`、`ValidationCache`。这些组件复用原有规则和数据检查，未复制另一套题库校验逻辑。

评审后修复了资源缓存命中时目标丢失/损坏的处理、后台源变更后的恢复、旧编辑页面的源冲突，以及环境身份未知时错误复用成功结果的问题。最后回归还恢复重复开发包名称的 404、补齐显式升级对未被当前题库引用的已安装目标的查找，并对后台关闭作有界等待与关闭后发布保护。源文件在规则执行期间变化时，旧成功结果不会写入缓存或发布为 `ready`。

开发描述与集合概览并行请求；两项成功后才替换当前页面，任何一项失败都会保留已有题目和输入。

编辑仍使用原来的逐题 `contentVersion`。新客户端额外携带可选 `sourceVersion`，绑定所见集合快照；保存成功后只推进同一编辑会话内匹配的来源版本。旧客户端兼容原合同，重复请求的已确认回执仍先于当前源冲突判断。

## 缓存与边界

- 成功校验缓存位于 `.state/validation-cache/v1`，仅存校验协议、键、校验和、导航结果，不存题目原始数据、答案、历史或凭据。
- 单记录最多 2 MiB，缓存最多 32 MiB、2,048 条；载入集合内存缓存最多 64 项，资源导入缓存最多 256 项。文件损坏、不安全路径或不可写时放弃缓存并重新校验。
- 校验身份包含真实源字节、规则、Schema、SDK、Node 可执行文件、runner 和实际规则依赖字节。不能用版本号或修改时间替代真实内容；无法确定环境身份时禁止复用成功结果。
- 任务入队所见身份只复用于匹配的目标范围；载入结束仍完整检查身份，变化时最多重试一次，再变化返回 `409 LIBRARY_CHANGED`。
- 普通题目快速读取复用已验证集合；显式打开集合重新检查完整环境。磁盘缓存命中仍执行宿主与资源检查，也不会跳过答题时评分、页面投影。
- 正式/开发资源和状态保持独立；测试使用副本，生产题库、答案、历史、AI 与网络配置不参与测量。

静态追踪确认，集合入口为选择状态命名空间先执行 `readCollection`，路由随后显式打开同一集合；冷缓存前一次会回退完整载入，后一次仍核实环境和源码。两个并行请求也在进入共享协调器前各自观察身份。集合概览对整本题库生成小题状态，再读取当前题并执行页面投影；规则按拓展分批，但每批启动独立 Node 进程并加载 Schema、规则与 VM。首题之后还顺序读取拓展页面和 SDK，再等待 iframe 注册。这些都比单纯解析 JSON 多。

# Node.js 宿主迁移

Git 基线为 `69dab26`，迁移在 `codex/node-host` 分支完成。启动入口现在运行原生 JavaScript 后端，只要求 Node.js 24；不调用 Java、JDK 或 Maven。Java 源码和旧测试暂保留作对照，退出正常运行路径。

## 实现范围

- 原生 HTTP、Host/Origin 校验、本机管理权限、局域网与 IPv6 连接、共用密码及登录限流。
- 一层题库／拓展分组、移动和改名、移入回收目录、开发版预览和发布、混合题型与精确版本绑定、`.qbank` 导入导出。
- 严格 JSON、原内容签名、原资源 ID、修订号、幂等回执、原子状态写入和编辑恢复日志。
- 作答、评分、小题大纲状态、草稿白板、编辑草稿、完成及再练一次、冻结历史、SDK 版本存档。
- AI 配置和本机密钥保护、能力测试、统一模型请求、整题／小题自动评分队列、重试、迟到结果保护及人工改分。
- 考试冻结、限时交卷、统一评分、继续／删除考试、考试历史；关闭历史时使用页面归属的临时状态。
- 两条既有简答专用升级路径。普通启动不升级题库、拓展或已保存的状态格式。

前端和拓展源码保持迁移前的内容，公开页面接口、规则接口与数据格式保持兼容。基础富文本开发样例中原有的未完成功能仍按原开发声明处理，宿主迁移不会将其自动变成正式拓展。

## 运行

Windows 双击产品根目录 `Start-QuizForge-Web.cmd`；其他平台先在 `core/` 安装锁定的依赖，再运行：

```text
node core/server/main.mjs --root . --port 8787
```

`-SkipBuild`／`-Rebuild` 保留参数兼容，不再编译 Java。启动脚本拒绝复用旧 Java 服务或已过期的 Node 实例；数据目录锁阻止多个 Node 实例同时写入。切换前保存作答并关闭旧服务，再启动新版。旧 Java 服务不支持新的目录锁，不能与 Node 服务共用正在写入的数据目录。

文件输入和目录元数据采用有界缓存；命中仍复核文件身份、纳秒时间和大小。规则环境缓存包含 Node 可执行文件、规则运行器与依赖内容签名。外部修改会重新校验，成功结果才进入持久缓存。原子替换只对 Windows 的短暂文件占用做有限重试，不删除原目标来完成替换。

## 验证

- 迁移前保存完整 Git 基线，真实练习目录不用于写入测试。
- 前端、规则与启动检查的 516 项原有测试通过；原生后端覆盖状态、恢复、历史、考试、AI、网络、分组、发布和压缩包的专项测试通过。
- 使用当前数据的隔离副本与旧 Java 后端对照：49 个题库目录一致；48 个现有题库的状态键、拓展／题目签名、作答概览、成绩汇总与历史一致；另一个专用 Java 生成的冻结历史样例一致。
- Java v1 的合成题库、状态和历史作为固定测试 fixture，读取不得改写原文件；重启和再练一次后仍保留旧冻结历史。
- Native CLI 在不包含 Java 或 shell 命令的 PATH 中可启动；专用升级模式正常退出并释放数据锁。
- 隔离浏览器检查旧作答、冻结历史、历史草稿切换及考试入口。自动 AI 测试使用模拟模型，未调用用户真实服务。

所有迁移脚本、对照副本、性能采样和测试临时产物位于产品 `.temp/`。测试命令：在 `core/` 执行 `npm test`；后端定向检查为 `npm run test:host`。这次迁移不是正式发布包验收；真实模型质量、公网／手机设备和最终内存收益仍需在实际部署中验证。

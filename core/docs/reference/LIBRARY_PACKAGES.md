# 题库分组与拓展导入导出

## 身份和引用

题库分组包含 `.group.json`：

```json
{"schemaVersion":1,"kind":"bank-group","id":"ec7a70a3-4f7d-4fa5-b176-d8cb51dd3a07"}
```

题库 `id` 使用稳定 UUID，同一题库更新保留 UUID，独立副本生成新 UUID。同一分组内题库 UUID 和显示标题分别唯一；不同分组允许相同 UUID，作答与历史独立。`version` 由作者维护，例如 `1.2.0`。分组没有版本号。

拓展 Manifest `id` 为稳定 UUID，同源不同版本保留 UUID，版本由作者维护。物理目录名唯一，显示名称可以重复。题库根默认绑定与逐题覆盖绑定使用：

```json
"extension":{"id":"f7aa4878-0e49-4f2f-a6d5-c6a7636b24ca","path":"extensions/single-choice"}
```

路径相对数据根目录，使用 `/`，与题库位置无关。宿主按路径定位再核对 ID，版本和哈希不是永久引用键。外部改拓展目录名需同步题库路径，缺失或身份不符时报错。样例在运行时自绑定所属实体，不改写样例文件。旧 `{id,version}`、`{development:叶名}` 继续兼容，候选不唯一时要求准确路径。

若新增同 UUID/版本但不同内容的拓展会使已有题库的旧 ID/version 绑定变得不明确，导入要求先完成该题库的路径迁移，不暗中改写已有题库。新路径绑定不受影响。

## 拓展目录与逻辑分组

**新规则中，拓展没有物理分组。所有拓展的独立目录都直接放在数据根目录的 `extensions/` 下；`.qbank` 包内也使用同样的平铺结构。** 每个拓展仍有自己的目录，不把不同拓展的源码混放在一起：

```text
extensions/
  single-choice/
    manifest.json
    examples/bank.json
    ...
  short-answer/
    manifest.json
    examples/bank.json
    ...
```

不创建 `extensions/<分组>/<拓展>/`。界面分组只由本地 `.state/extension-groups.json` 记录，成员是实际拓展路径；修改名称、移动或删除逻辑分组不搬动、复制或删除代码。逻辑分组不随包导入导出。

导入新增实体一律安装到 `extensions/<最终目录名>/`，默认在界面中显示为未分组；目录重名加序号。复用已有实体时保留其本地路径和逻辑分组，不复制一份到根目录。

旧物理分组仅为兼容既有数据继续读取，首次逻辑分组管理继承其分组关系；兼容读取不代表新规则允许创建物理分组。旧目录的实际迁移单独执行，不在启动或导入时擅自搬动、去重。

## 包格式 2

只按题库分组导出 `.qbank`，ZIP 容器：

```text
quizforge-package.json
question-banks/<分组>/.group.json
question-banks/<分组>/<题库UUID>/bank.json
question-banks/<分组>/<题库UUID>/assets/   # 有图片时
extensions/<实际目录>/                  # 平铺，无拓展分组
```

清单字段为 `format:"quizforge-bank-group"`、`formatVersion:2`、`group:{id,name}` 和 `extensions:[{path,id,version,hash}]`。hash 为64位小写十六进制摘要。只包含实际关联拓展和资源，不含作答、草稿、历史、设置或密钥。只在暂存副本改引用，本地源文件不变。

导出优先读取暂存副本中的题库 `assets/`，不要求题库曾被打开或图片已登记到主机资源缓存。拓展嵌套样例也可使用拓展根目录的 `assets/`；旧独立 JSON 题库缺少本地图片时仍从主机资源存储补齐。引用图片保留 SHA-256、类型、4 MiB 单图及包总量检查，本地图片损坏时拒绝导出，不用缓存掩盖损坏文件。包格式 1 与 2 均适用。

无 `.group.json` 或仍包含非 UUID 题库 ID 的旧分组继续使用包格式 1 的旧冲突保护，不因导出自动迁移。包版本与题库 JSON `formatVersion:1` 独立。

兼容格式 1 支持读取旧版、叶名及 `{id,path}` 绑定，导出时仅在暂存副本中转换为该格式的 ID/version 引用；不要求删除旧字符串 ID 题库，也不改变源身份。格式 1 保留旧包目录布局，只有格式 2 使用新的拓展平铺包结构。混合旧 ID 与 UUID 的分组完成数据迁移后才改用格式 2。

## 导入规则

1. 隔离暂存并校验标识、大小、目录、声明、题库规则、图片引用，尚不安装。
2. 按分组 UUID 找本地分组，没有则新建，目录重名加 `（2）` 等序号；找到则沿用原分组名称。
3. 在目标分组按题库 UUID 匹配。未匹配新增；导入版本较高整库替换；相等、较低、缺失或不可比较则显示双方版本，让用户选保留本地或替换，默认保留。数字段比较：`1.10 > 1.2`，缺尾段视为零。题库不做哈希比较。
4. 全部本地拓展按 UUID 找候选，仅计算 UUID 重复候选的规范化包哈希。与导入清单一致则复用本地路径和逻辑分组，跳过文件；不一致则直接新增到 `extensions/<最终目录名>/`，默认未分组，目录冲突加序号，不创建物理分组，不改 UUID、版本、显示名称和代码。多个匹配候选优先同路径，否则按路径排序选择，不删除其他实体。
5. 汇总本次路径对应关系后，遍历实际安装/替换的题库一次，只修改根默认与逐题 `extension` 字段；保留题库、无关题库、正文及历史不改。不建立永久映射表。
6. 安装；题库标题重复加序号。替换沿用 UUID、原位置和历史命名空间。原题库备份至 `.trash/library-import/` 并记录原路径收据；安装异常回滚本次文件移动。冻结历史不改写，受内容修改影响的当前答案按已有规则备份并重置。

导入信任导出清单哈希，不重算导入拓展哈希；哈希用于去重，不是签名或防篡改证明。包仍执行结构与规则校验。哈希覆盖导出器规范化的全部文件：相对路径排序，JSON 规范化内容指纹，其他文件 SHA-256，再生成整体指纹；外层目录名和本地分组/显示标签不参与。用户确认计划最多保留10分钟，同时最多3份；取消、过期、服务关闭清理暂存。

导入校验在隔离暂存目录中按实际拓展合并规则请求，最多两个规则进程并行、每轮最多准备64个集合。合并保留原请求边界，边界之间重置规则 VM；单批数量、大小和执行超时沿用原限制。合并失败时分别执行原请求，避免合并超时误拒有效题库。同一次校验复用拓展读取与运行环境检查，结束时重新核对全部来源及运行环境；题目、拓展样例、资源及私有路径校验均保留，不以包内哈希代替规则校验。

## 迁移交接

个人数据迁移另行执行，先停止服务并备份整个数据目录。本次宿主改动不批量改写题库或已安装拓展。

- 分组写 `.group.json`；题库写稳定 UUID 和作者版本。题目/小题 ID、data、outline、features、资源保持。
- 拓展迁移身份后，根默认及逐题引用改为 `{id,path}`；旧字符串拓展 ID 仍兼容。不合并内容不同的实体，不改正文。
- 旧集合 ID/状态键需对应新 `g.<分组UUID>.<题库UUID>`，新状态键为 `bank:g.<分组UUID>.<题库UUID>:mixed`。备份后迁移状态文件外层 `collection`；冻结历史内部题目、页面、评分、笔迹不改写。考试关联、编辑草稿与 AI 任务作用域另行核对，不能只替换 bank.json 的 id。
- 宿主内移动 UUID 题库迁移当前状态文件并留备份；`bank-locations.json` 记录路由及移动事件，维持考试关联。外部手动移动不自动推断作答实例。
- 不预写题库哈希或永久拓展哈希引用；导出时生成包清单哈希。

迁移后验证题库、样例、图片、练习、考试、旧历史及新包往返。

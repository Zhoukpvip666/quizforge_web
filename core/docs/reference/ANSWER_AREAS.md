# 手写答题区（Extension API 1.5）

答题区是宿主提供的可选组件。拓展决定放置位置、稳定区域 ID、所属题目／小题和答案 Schema；宿主提供笔迹交互、可选文字输入、校验、提交出图与冻结组件。带明显紫色边框的区域内内容是答案，区域外普通草稿不会自动送给 AI。旧拓展不需要修改。

可直接打开项目自带“基础题型 → 基础题型展示”第 11 题“手机拍照的信息处理流程”体验。配套 [答题区拓展](../../../extensions/基础题型/答题区) 含真实打字、统一手写、图片上传、保存、人工／AI 评分及默认高度编辑。

## 声明与使用

Manifest 声明 `requiresApi:{major:1,minMinor:5,capabilities:["practice","answer-areas","answer-state","resources","lifecycle"]}`；需要 AI 时再加 `ai-grading`，人工评分加 `manual-review`。能力声明不授予写权限。只有明确声明 `answer-areas` 的当前页面才获得 `QF.answerAreas`；API 1.0–1.4 的冻结页面不注入此组件。

`QF.answerAreas` 是冻结对象，当前实现为 `{version:"1.4.1",formatVersion:1,mount(container,options)}`。1.0.0／1.1.0／1.2.0／1.3.0／1.3.1／1.3.2／1.4.0 冻结历史继续使用原组件；现有纯笔迹文档原样可读。页面 `onLoad` 中创建一次，之后恢复数据，不要每次评分更新都重建。

组件 1.4.0 修复浏览器缩放的显示坐标换算：落笔、交互区域和答题裁剪统一换算到画布局部 CSS 坐标，DPR 仅用于清晰度。页面／视觉视口变化时在下一动画帧刷新范围，即使宽度未变也更新位置；延续 1.3.1 的尺寸通知防循环处理。显示缩放不改写已保存的笔迹坐标。旧文字／笔迹答案原样可读；1.4.0 的可选图片能力需显式开启并适配 Schema，见下文。

组件版本与 Extension API 独立。使用宿主统一笔迹与截图范围的页面应检查 `QF.answerAreas.version` 至少为 1.3，并传 `sharedInk:true`；在旧组件上明确提示更新宿主；不能仅凭 API 1.5 判断早期开发实现已具备这些行为。独立示例包含此检查。

```js
let context, area;
const unwrap = reply => {
  if (!reply.ok) throw new Error(reply.error.message);
  return reply.data;
};
QF.page.register({
  onLoad(value) {
    context = value;
    area ||= QF.answerAreas.mount(document.querySelector('#answer'), {
      id: 'response', label: '正式答案', width: 760, height: 480, allowText: true, sharedInk: true,
      async onChange(document) {
        const report = unwrap(await QF.page.reportAnswerState({
          status: document.strokes.length || document.text?.trim() ? 'draft' : 'unanswered'
        }));
        unwrap(await QF.save({
          purpose: 'draft', data: {answer: {area: document}},
          answerStateId: report.stateId
        }));
      }
    });
    if (value.answer?.area) area.setDocument(value.answer.area);
  },
  onFlush: () => area.flush(),
  onDispose: () => area.destroy()
});
```

示例省略了拓展自身的保存队列。实际拓展应串行保存，并在提交前 `await area.flush()` 和自己的保存队列；收到 `{ok:false}` 必须抛错，不能把失败当成保存成功。多区域答案应一起保存到本题自己的答案对象中，每个区域只占一个稳定位置，不能在同一答案中重复放置相同区域 ID。参考完整可运行实现：[`core/examples/handwritten-short-answer`](../../examples/handwritten-short-answer)。

### mount 参数与实例

| 参数 | 说明 |
| --- | --- |
| `container` | 当前 iframe 中的独立容器；禁止嵌套答题区 |
| `id` | 本父题内唯一且稳定的区域 ID；ASCII 字母／数字开头，后续可含 `. _ -`，总长至多 120 |
| `targetId?` | 可选大纲小题 ID；省略属于父题。提交到宿主时必须属于当前父题的 `outlineItems`；不是其他父题的 ID |
| `label?` | 展示名称，最多 100 字 |
| `width?` | 逻辑宽度，默认 760，160–1600 的整数 |
| `height?` | 初始逻辑高度，默认 480，120–3200 的整数；拓展将其存入题目 data，由自己的编辑页调整 |
| `allowText?` | true 时在同一个框内提供普通 textarea，无输入标签切换。1.3 统一笔迹模式默认开启文字；旧组件默认 false。答案 Schema 必须允许可选 `text:string`（至多 20000 字符），文字与笔迹同时可见 |
| `sharedInk?` | 1.3 新接入必须设为 true：区域只定义文字与截图范围，手写全部来自宿主草稿画布。省略时沿用 1.2 独立笔迹实现，不向旧 Schema 增加字段 |
| `onChange(document)` | 必填。完整笔迹发生变化后调用，应返回实际保存的 Promise，并传播失败 |

实例提供：`getDocument()`（独立副本）、`setDocument(document)`（恢复，不触发保存）、`isEmpty()`（文字仅空白且无笔迹）、`flush()`（完成当前笔并等待保存，失败拒绝）、`destroy()`。`setDocument` 不允许切换区域 ID、targetId 或逻辑宽度；新一轮空答应由拓展明确恢复空文档。只读／暂停／销毁后的实例不能写入。统一笔迹模式的撤销、重做、擦除、框选和清空由宿主草稿工具管理；实例 `clear()` 拒绝调用，`undo()`／`redo()` 不执行修改。文字用普通输入框编辑。

## 交互与坐标

- 草稿模式且 `canSave`、`canWhiteboard` 均为 true 时可手写，练习模式显示同一份笔迹。开启 `allowText` 后，练习模式直接在框内打字，草稿模式选择“操作／移动”工具后打字，选择画笔则在同一个框里写。文字输入只要求 `canSave`，因此 `whiteboard:false` 仍可打字。提交后及历史只读，文字和笔迹同时显示。
- 区域不再重复画笔／颜色工具，统一使用草稿工具栏的画笔、整笔擦除、颜色、粗细及“仅笔书写”。鼠标与触控笔可用；关闭宿主的“仅笔书写”后，手指也可写。框内外使用同一个宿主 canvas、平滑压力笔刷和撤销栈，一笔可以跨越边界，撤销顺序按实际书写顺序。整笔擦除、框选移动／复制／删除均可跨范围操作。全局清空会明确说明清除本题全部手写笔迹（包含答案范围），保留打字内容，支持撤销。普通作答不展示加高或尺寸控件，失败时可重试保存。区域没有独立画笔层。重答会移除上次正式答案对应的整条源笔迹，保留其他草稿。
- 框内没有 placeholder、示例文字、底部提示或单独工具；上方且截图范围外仅保留“下方答题区的打字以及手写输入，都将作为答案进行评分”。空框不会将这句提示当成答案。
- CSS 可以适应容器宽度，内部文字和笔迹一起按逻辑画布缩放；手机、电脑和宿主缩放不重写坐标。画布裁剪边界处的笔迹，文字增加时可扩大文档高度以避免隐藏答案，超过上限则保留输入并提示精简。文字与笔迹可重叠，用户自己负责排版，不自动移动笔迹、识别涂改或解决内容矛盾。富文本仍由拓展另行管理；照片须显式开启下文图片能力。
- 单区域不超过 400 万像素、1000 笔／2 万点／2 MB；单个父题最多 16 区域、总高度 12000、总像素 800 万、总点数 4 万；PNG 不超过现有图片资源 4 MiB 上限。生成图片有总绘制工作量上限，超限明确报错并保留已保存答案。
- 手机、平板和触控笔需要真实设备验收。合成 PointerEvent 测试不是实机证据。

## 答案格式与提交

拓展把以下对象嵌入自己的答案 Schema（不是富文本 doc 节点）：

```json
{
  "type":"qf-answer-area", "formatVersion":1,
  "id":"response", "width":760, "height":480,
  "strokes":[{
    "id":"stroke-1", "color":"#334155", "width":3,
    "points":[{"x":20,"y":30,"pressure":0.5}]
  }]
}
```

统一笔迹模式增加 `inkSource:"draft"` 和可选 `anchor:{x,y,width,height}`（宿主草稿世界坐标的范围）。Schema 必须允许这两个字段。笔迹 ID 沿用源笔迹 ID，范围内所涉及整笔保存在答案中，交叉笔画的点可能位于区域外，最终出图严格裁剪。此模式笔宽 0.05–64，点坐标范围 ±2000000；anchor 的 x/y 范围 ±1000000，width 为 1–10000，height 为 1–20000。拓展应原样保存组件返回值，不自行计算坐标或依赖 anchor 定位题目。旧格式不含 inkSource，仍保持笔宽 0.5–16、点位于区域内。颜色为六位十六进制，压力 0–1。`targetId` 是可选字段。1.1.0 增加可选 `text` 字段：普通字符串、至多 20000 字符；未输入文字时纯笔迹文档不自动增加此字段。宿主只对声明了 `answer-areas` 的拓展处理这些标记对象；其他拓展继续按自己的规则校验和保存，旧答案结构不改变。

草稿保存不生成图片。单题提交、完成练习统一提交及考试交卷都在既有答案事务中，含手写笔迹或图片时使用本次答案版本的已校验文字与笔迹生成**完整逻辑区域** PNG，不依赖浏览器当前视口。统一笔迹模式使用与宿主一致的压力曲线和平滑笔刷，并以 2 倍逻辑分辨率出图；浏览器画布按设备像素比例显示，避免额外低分辨率笔迹层。先绘制图片和文字，笔迹叠在上面；工具栏、普通草稿和其他题目不进入图片。纯文字不出图。宿主会移除浏览器上传的 `snapshot` 并重新生成，写入如下字段后才交给拓展的 `validateAnswer`／`grade`：

```json
"snapshot":{"type":"image","attrs":{"assetId":"64位小写SHA-256"}}
```

因此答案 Schema 必须允许可选 `snapshot`。它是不可变图片资源，不是可修改的图片 URL；笔迹仍保留在答案里。空区域不生成图片。生成失败或持久化失败不会提交成功，已有已保存笔迹保留，可重试；未确认保存的输入由页面保留并阻止正常离开。不存在浏览器任意指定 AI 评分材料的新 HTTP 入口。

## AI、考试与历史

`prepareAiGrading(data,answer,context)` 按区域判断：有笔迹或图片则只返回 `{type:"image",assetId:area.snapshot.attrs.assetId}`，图片已经包含框内的文字、图片与笔迹，不再重复返回该区域的 text；没有笔迹和图片但有文字则返回 `{type:"text",text:area.text}`，不要求视觉模型。多小题沿用现有 `targetId`／`targets`，由拓展选择属于该小题的区域、准备参考答案与分值，并通过原有 review 规则采纳结果。AI 启用、视觉模型、失败重试及人工评分沿用现有流程。

混合答案使用运行依赖 `@napi-rs/canvas` 将普通文字和笔迹合成 PNG。Windows 使用系统 Arial／微软雅黑，其他部署主机需具备支持作答文字的系统字体。打包脚本包含该依赖及当前平台原生模块；纯文字仍走文本路径，旧格式纯笔迹保留原渲染路径。

## 编辑答题区高度

高度是题目内容配置，不是浏览器偏好或草稿相机参数。拓展编辑页通过 `QF.editor.register().getDocument()` 返回新的 `data.areas[].height`；保留区域 id，正常作答用该高度 mount。示例提供 120–3200 px 的数值输入和比例预览，支持宿主编辑草稿恢复。实际尺寸仍受单区域像素上限约束。

恢复已保存答案时不得裁剪笔迹，示例使用 `Math.max(saved.height,configured.height)`；普通作答不提供尺寸按钮。通过宿主保存高度属于修改题目内容，沿用既有编辑事务，会重置当前题作答并归档原轮次；已完成历史的尺寸和答案不变化。示例编辑页明确提示该规则。制作其他题型时，应在自己的编辑页公开对应 height 配置，不能指望宿主猜测 data 中的字段。

有作答但尚未判分时应返回 `gradingStatus:"pending",score:null,correct:null`，大纲显示“已提交，待评分”。不能把图片生成、模型连接或评分失败伪装成完成或自动零分。修改／重答后，原有答案摘要、提交代次和评分代次检查拒绝旧任务结果。

考试只保存笔迹，交卷后统一出图、锁定及评分；到时交卷只处理服务端已保存的答案。正在写但未结束／未保存的笔画不属于已经确认的考试答案，不延长既有考试截止时间。关闭历史时笔迹、图片与考试状态使用同一临时会话资源存储，不新增隐式持久化。

完成历史同时保存答案文字、笔迹、当时的 PNG 引用和当时组件源码／样式；浏览手写历史优先显示提交图片，不用当前拓展或组件源码重新出图。已有历史保持其原 API 和冻结页面，1.0.0／1.1.0／1.2.0／1.3.0／1.3.1／1.3.2／1.4.0 实现文件保留不覆盖。

## 同框图片与自动增高（组件 1.4.0）

`sharedInk:true,allowImages:true` 的标题栏显示区域名称、说明“下方区域的文字、手写和图片均作为答案进行评分。”、拍照和上传图片。横线以下的内容平面才是评分范围。输入框无占位文字，支持剪贴板图片粘贴。组件 1.4.1 中，双击／双触图片进入调整，拖动图片移动、拖动四角等比缩放，点击图片外或按 Esc 完成。图片正下方的 × 打开删除确认，取消保留原图；不再显示常驻图片编辑栏。选框、手柄、删除按钮和确认框都浮在答案上，不挤动文字或改变答题区高度，也不进入评分图。小屏幕下手柄、删除和确认控件保留可点击的显示尺寸。草稿中双击图片不落墨点、不擦除笔迹；单次落笔和连续书写仍使用原画笔。手机拍照请求系统 `capture="environment"` 入口，实际选择界面取决于设备和浏览器，桌面通常是文件选择器。

`height` 是编辑时设置的默认高度。文字、图片需要更多空间时向下增高；本区域新笔迹从框内开始、接近底部时预留下一段空白。删除内容不自动缩短。宽度和已有内容的局部坐标保持不变，各设备整体等比显示；页面整体滚动，输入框不做内部滚动。高度仍受 3200、单区 400 万逻辑像素、本题总尺寸限制约束，超限的未保存输入保留在页面并阻止 flush／提交。只有新的作答触发扩高，不扫描框外草稿来扩高。范围增高与下方范围移位时，宿主为原有普通草稿让出空间，后续答题区的已归属笔迹和撤销／重做记录同步移动。浏览器视口尺寸变化只更新显示，不增长或保存答案。

文档增加可选 `images` 数组，至多 8 张；没有图片的旧文档不增加此字段：

```json
{"type":"image","id":"image-1","attrs":{"assetId":"64位小写SHA-256"},"x":16,"y":64,"width":300,"height":200}
```

坐标和尺寸位于同一原稿平面，图片必须完整处于区域内。Schema 应允许此数组和字段；按 `strokes.length || text?.trim() || images?.length` 判断作答。有图片或笔迹时，评分材料只引用宿主生成的一张完整合成图；只有文字时继续传 text。`prepareAiGrading` 需把 `images?.length` 也列入使用 snapshot 的条件。`allowImages` 默认 false，拓展完成 Schema 与评分适配后显式开启；旧拓展不自动出现图片入口。新图片通过现有 `QF.resources.put/get` 保存，标准 `type:image`／`attrs.assetId` 引用参与现有资源检查和历史保存，不保存文件路径、外部 URL 或浏览器 Blob URL。

图片入口接收至多 20 MiB、4000 万像素的可解码图片，较大图片缩至最长边 2560 并压缩至 4 MiB 后上传。单次提交解码图片总计最多 1600 万像素。处理、上传和保存纳入 flush，失败保留原答案并阻止提交。只读／历史不显示上传入口，也不接受粘贴或移动。使用新图片能力的拓展需同步答案 Schema 和 AI 材料准备；现有纯文字／笔迹拓展保持原数据格式可读。当前组件源码位于 `shared/answer-area/1.4.1/component.js`，模型沿用 `1.4.0/model.js`，旧版组件和模型继续保留，用于冻结历史。

最终评分由宿主按完整逻辑范围合成：白底、图片、文字、笔迹依次绘制。页面下方尚未滚动看到的内容照常包含，标题、提示、按钮和图像调整控件不参与。图片丢失／解码失败、文字超出高度或资源保存失败时不生成部分答案、不提交成功。打字的点击穿透使用独立透明命中层；可见笔迹仍由宿主唯一画布显示，不再为输入框裁掉笔迹。

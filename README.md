# QuizForge Web 第一版

通过浏览器练习和制作题库，Java 后端保存数据。支持单选、富文本简答、人工／AI 评分、白板草稿和只读历史；题型由独立拓展提供，同一本题库可以混用多个题型。

第一版功能范围已确定，后续以修复和发布验证为主。当前目录是源码与启动入口，尚未提供内置运行环境的正式发布包。Web 版独立于 QuizForge V2，数据和包格式不互通。

考试默认开启并保留普通练习；题库文件未声明 `features.exam` 时，页面顶部显示“开始考试”，只有声明 `"features":{"exam":false}` 才关闭入口。功能开关由题库文件控制，列表编辑仅修改名称与分组。开始前选择时长或不限时；限时到点自动交卷并锁定答案，交卷后统一评分。AI 评分失败可重试或人工评分。考试与练习分开保存，入口内可继续考试／查看成绩；关闭历史的题库只保留原页面会话内存。拓展页面需独立处理保存、提交权限，详见 [考试模式](core/docs/EXAM_MODE.md)。

## 启动与停止

需要 **JDK 21+、Node.js 24**；首次构建或重建还需要 **Maven**。双击根目录的 `Start-QuizForge-Web.cmd`，或在产品根目录运行：

```powershell
.\Start-QuizForge-Web.cmd
```

首次自动安装 Node 依赖并构建 Java。服务就绪后自动打开 `http://127.0.0.1:8787/`；后续启动复用未改变的构建。公共富文本组件的构建产物已包含，运行时无需从网络加载编辑器。请保持启动窗口打开，按 **Ctrl+C** 或关闭窗口停止服务。

| 启动参数 | 用途 |
| --- | --- |
| `-Rebuild` | 强制重新构建 |
| `-SkipBuild` | 跳过源码更新检查；缺少 JAR 时仍构建 |
| `-NoBrowser` | 启动后不自动打开浏览器 |
| `-Port 端口号` | 更换本机入口端口 |

启动脚本对同一产品目录只运行一个实例。重复启动时，仅复用后端未更新的当前服务；源码、POM 或 JAR 比服务更新，或指定重建时，会提示先保存作答并关闭原启动窗口。不会自动停止当前服务或其他占用端口的程序；`-SkipBuild` 也不会绕过运行中服务的版本检查。

普通启动不升级题库绑定的拓展版本。当前随附简答题库使用 1.3.0，无需运行升级命令；旧版专用迁移及备份要求见 [核心源码说明](core/docs/CORE_SOURCE.md)。

## 浏览与管理

- 正常模式左侧只显示题库；在本机设置开启**开发者模式**后，可切换到拓展列表，浏览正式版和带开发标签的拓展。
- 点击列表项直接切换内容，不再使用顶部标签栏。题名栏保留两侧栏的显示／隐藏按钮；桌面偏好在本浏览器保存，窄屏采用抽屉。
- 桌面可拖动左侧列表右边缘调整宽度（180–480px），双击恢复默认宽度；支持键盘调整。宽度在本浏览器保存。
- 题库、拓展按真实文件夹显示**一层可折叠分组**，也允许未分组项目和空分组。分组不能再放入其他分组；浏览标题显示所属分组。
- 本机列表标题旁的 `+` 新建分组。项目旁的编辑按钮修改名称或所属分组；分组编辑只修改名称。删除前会确认，远程设备不能管理目录。
- 移动、改名不改变题库 ID、拓展身份、作答或历史。拓展改名只保存本机显示名称，不修改正式代码、ID 或版本；仍被题库引用的拓展及其分组不能删除。

删除内容移到 `.trash/library/<记录ID>/content/`，同目录的 `receipt.json` 记录原路径；作答与历史保留。需恢复时先停止服务，再按收据移回原目录，处理同名冲突后启动。删除分组包含其中全部文件，包括未显示的文件。也可以在文件管理器中整理目录，再点击列表的刷新按钮。

每个独立拓展提供一本仅包含本题型的样例题库，可以有多道变体；样例使用普通题库的练习、切题、编辑、白板和历史流程，其状态与正式题库分开。多个拓展可放在一个分组中，分组不产生共同版本或混合样例。详见 [独立拓展与分组](core/docs/EXTENSION_GROUPS.md)。

## 练习、评分与历史

- 支持上一题／下一题和矩阵大纲跳转；大纲先保留题序，再将连续的同一大题型放在一起，不合并被其他题型隔开的项目。每道题可显示自身编号或小题编号，两者互斥。状态只有**未作答、正确、错误**：未提交为未作答，提交后满分为正确，否则为错误；待评分的分数仍保持为空。
- 单选支持选择、提交、判分与解析。富文本简答 1.3.0 提交后自动保存默认 0 分，人工滑条步长为 0.5 分，调整后自动保存，无需确认；可使用人工或 AI 评分。
- 最后一题后显示应用统一绘制的分值卡，汇总本轮得分、总分、提交进度和待评分题数，也可从大纲打开。已提交题全部评分后可完成本轮，未提交题计 0 分。
- 完成后结果保存为只读历史，点击**再练一次**开始新轮，清空本轮答案和白板并返回题目，旧历史保留。
- 题名栏时钟按钮打开历史列表，每条记录可删除。历史冻结当时的题目、答案、评分、解析和白板，不会因后来改题而变化，也不会重新请求 AI。
- 历史可切换练习／草稿布局；草稿恢复当时的纸面、笔迹和视角，允许移动、缩放和全屏查看，不允许书写或改动快照。历史中的切题和小题定位继续可用。

开启历史时，练习答案与白板自动保存，可在刷新网页或重启服务后恢复。题库根的 `features` 可以分别关闭编辑、白板、历史和考试，未声明的项默认开启；**关闭历史也关闭答案、分数、白板、完成状态、练习图片和 AI 任务的持久化**，仅保留当前浏览器页面会话中的数据。编辑仍开启时可以保存题目文件和编辑图片。拓展样例功能声明默认四项全开。详见 [题库格式与功能开关](core/docs/QUESTION_BANK_FORMAT.md)。

## 白板与手机布局

草稿模式提供画笔、压力线宽、整笔橡皮、移动、撤销／重做、常用笔色和纸色。工具栏左侧拖动柄可移动工具栏，双击恢复位置；缩放按钮固定在左下角。“操作题卡”工具允许选择答案和提交。默认白色纸面，方格／点阵绘制在题卡下方，笔迹绘制在题卡上方；切换模式不改写笔迹坐标和草稿视角。

“框选笔迹”用鼠标、手指或手写笔从矩形的一角拖到对角，选中完全位于框内的整条笔迹；拖动选区可移动，也可复制或删除，操作支持撤销。“区域截图”以同样方式框取题目与草稿，预览后可下载 PNG 或复制图片，不包含工具栏。复制图片需要支持图片剪贴板的浏览器，并使用 HTTPS 或本机地址；普通公网 HTTP 地址可继续下载。截图在本机合成，复杂 CSS 的还原程度取决于截图组件；只读历史也可截图，但不能修改笔迹。

全屏按钮只在草稿模式显示，同时请求浏览器全屏并隐藏网页侧栏、顶部题名栏，让题卡、白板和工具占满可用区域；退出后恢复原布局。不支持全屏时隐藏入口，请求失败时提示。Android 地址栏及系统栏的实际行为由浏览器和设备决定。

手机宽度不超过 600px 时，练习、历史、编辑和分值卡铺满内容区；长题纵向滚动，切题箭头在底部。草稿工具栏使用紧凑按钮，隐藏左下角缩放控件，改用双指缩放。普通手机作答页隐藏笔迹叠层，进入草稿后查看与书写。支持手写笔书写、手指移动和双指缩放；真实设备的延迟、掌触与软键盘体验仍需验收。

## 题目编辑与富文本

题名栏铅笔按钮进入当前题型的编辑器，编辑能力由拓展提供。左右箭头和大纲可切题，未完成内容自动保存为服务端编辑草稿；切换前保存草稿并释放旧页面，返回时恢复正文。撤销栈只在当前编辑页面保留。

保存全部修改会校验修改过的题，再逐题保存；只重置内容改变的题目的当前作答，其他题目与旧历史保留。校验失败保留输入并定位问题；多题保存中途失败时保留已保存题与剩余草稿，不能视为整库原子保存。取消编辑前确认放弃未保存修改。

富文本使用结构化 JSON 与内容哈希图片，公共编辑服务与拓展解耦：基础工具内联显示，右上角展开高级编辑，提供字体、字号、颜色、高亮、段落、链接、公式、表格和图片尺寸等工具。支持拍照插入答案，手机请求后置摄像头，大照片自动缩小后上传；具体选择界面由浏览器和系统决定。高级编辑与实际练习使用相同正文宽度和文档格式；图片可拖动四角等比缩放。Tiptap 编辑器分包在编辑时加载，各拓展不复制组件；升级编辑器无需升级题型。详见 [富文本服务](core/docs/RICHTEXT_SERVICE.md)。

## 题库分组导入与导出

第一版**只导出题库分组**，不单独导出题库或拓展分组。本机题库列表标题旁导入 `.qbank`，题库分组操作栏导出整组；未分组题库需先移入分组再导出。

导出自动收集组内每道题实际依赖的全部正式拓展及图片，即使拓展位于其他分组或未分组，也会在包中统一放入与题库分组同名的拓展分组。原目录和题目绑定不改变，不包含无关拓展；引用开发版的题库须先完成并获准发布对应拓展。

`.qbank` 使用 ZIP 容器，结构如下：

```text
我的题库组.qbank
  quizforge-package.json
  question-banks/
    我的题库组/
      <题库ID>/bank.json
      <题库ID>/assets/                  # 有资源时
  extensions/
    我的题库组/
      <拓展ID>@<版本>/                  # 完整的独立正式拓展
```

标识文件内容为 `{"format":"quizforge-bank-group","formatVersion":1,"group":"我的题库组"}`。普通 ZIP 改后缀不会成为可导入的题库包。Web `.qbank` 不兼容桌面 V2 的旧包格式。

导入先验证包标识、版本、目录结构、题库、拓展和图片引用，再安装到对应目录。已有相同题库 ID 或相同拓展 ID／版本且内容一致时跳过，保留原安装位置；内容不同或目标目录冲突时停止整次导入，**不覆盖已有数据**。安装过程发生错误时撤回本次已安装项目。

包不包含作答、白板、历史、连接密码或 AI 设置，不能代替完整数据备份。上传上限 64 MiB、解压上限 128 MiB、单文件上限 8 MiB、条目上限 10,000；越界路径和重复路径会被拒绝。包内含可运行拓展代码，请使用可信来源；格式校验不代表来源认证。

## 网络连接

本机地址 `http://127.0.0.1:8787/` 无需连接密码，只有主机本体可以修改网络、AI、开发者设置或管理题库目录。

左下角设置 → **网络连接**，分别开启局域网／公网入口。两者共用连接端口（默认 `8788`）和至少 8 个字符的密码，保存后重启仍恢复。密码留空保留原密码；修改连接配置会使已有远程登录失效。其他设备使用设置中显示的地址并输入密码。

连接端口自动支持 **IPv4／IPv6 双栈**，系统未启用 IPv6 时使用 IPv4，不需要单独启动指令。局域网地址列表包含可用的 IPv6 地址；带接口作用域的链路本地地址不作为浏览器地址展示。开启公网连接后，设置会列出本机检测到的公网 IPv6 候选地址，点击即可填入公网访问地址；没有检测到时仍可填写指向本机的域名或代理地址。

IPv6 直接部署：确认主机拥有公网 IPv6、客户端也能访问 IPv6，在设置中开启公网连接、设置共用密码，并填写 `http://[你的公网IPv6地址]:8788/`（IPv6 必须放在方括号内，端口与连接端口一致）。按实际网络放行主机及路由器的 IPv6 入站防火墙。候选地址只表示本机拥有该地址，不代表外网已经连通；IPv6 地址发生变化后需要更新访问地址。也可通过具有 AAAA 记录的域名及 HTTPS 反向代理访问，代理仍应连接密码保护的端口。

公网还需填写实际根地址，例如 `https://quiz.example.com/`，不带子路径。需自行配置反向代理／端口映射、DNS、证书及防火墙，开关本身不建立公网通道，也不保证地址可达。建议以 HTTPS 代理连接端口，并保留原始 Host；例如已有域名及证书的 Nginx：

```nginx
location / {
    proxy_pass http://127.0.0.1:8788;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 8m;
}
```

**公网代理只连接密码保护的连接端口，不要代理 `8787` 本机管理入口。** 连接端口即使经回环代理访问，也要求密码且不能修改管理设置。服务校验配置的 Host 和写入请求的 Origin，不自动修改 Windows 防火墙。

电脑需持续运行。各设备共用当前题库、作答、草稿与历史，这是个人跨设备访问，不是多账户系统。原临时口令方式 `Start-QuizForge-Web.cmd -Lan` 仍保留，局域网常用连接优先使用网页设置。

## AI 辅助评分

设置 → **AI 评分**，填写 OpenAI 兼容基础地址、模型名称和 API Key，开启并保存。地址不包含 `/chat/completions`，系统自动追加。界面只保留开启评分、自动评分、服务地址、模型名称和 API Key；输出格式自动检测，默认最大输出 8192 Token、超时 90 秒，技术参数不在设置中展示。云端地址使用 HTTPS，本机／私有局域网模型允许 HTTP。

“提交答案后自动 AI 评分”默认关闭，开启后对支持 AI 的题目自动发起评分；也可在题卡手动点击。响应格式校验后交给拓展处理，由拓展决定并保存最终得分，反馈包含最终得分、建议及理由；人工改分自动保存并保留 AI 理由。点击“测试模型”会先保存当前配置，再检测文字连接、评分输出和随机图片识别，显示并保存完整报告；通常发送 2 次请求，遇到 JSON 模式不兼容时最多 3 次，可能计费。图片识别通过后自动开启图片评分，更换地址、模型或密钥后检测结果失效；网络故障显示无法判断，不能等同于不支持视觉。基础测试通过不保证复杂图表或手写识别准确。

支持小题评分的拓展可使用 `QF.ai.grade({targetId:"part-1"})`，通过 `getTask({targetId:"part-1"})` 恢复该小题任务。不同小题可同时发起，模型请求由有界队列依次执行，结果按稳定 ID 分别保存，由拓展合并成整题成绩。省略 targetId 沿用整题评分，现有简答拓展无需升级；设置里的提交后自动评分仍默认请求整题，不自动枚举小题。接入方式见 [拓展 API](skills/quizforge-bank-builder/references/extension-api.md)。

网络临时错误有限重试；无效 JSON、越界分数或精度错误最多修复一次，每个任务合计最多 3 次模型调用。失败可手动重试，新结果保存前保留原成绩；重答、改题、人工改分或完成本轮后，旧任务结果不能覆盖新状态。服务中断的任务不会自动再次请求模型，历史查看不调用模型。

模型请求统一由后端网关发送，拓展只提供题干、已提交答案、合并的参考答案与评分依据，以及协议版本、满分和精度。满分和精度描述本次 AI 请求，不强制对应整题；宿主只检查响应格式和有效数字，分数范围、取舍、舍入及小题汇总由拓展处理。旧拓展的独立评分依据由宿主合并，不必升级拓展。提示词采用固定系统规则加三个材料分区，模型返回 score 与 feedback。拓展不持有密钥或直接调用模型。密钥持久保存在后端 `.state/ai/profile.json`；本机管理页面通过专用接口读取，密码框保留已保存值并遮蔽显示，可直接删除或替换后保存。普通状态、拓展和远程设备不接收密钥，关闭设置会清空页面中的值，不要分享配置文件。当前已用模拟服务验证协议、重试和保存流程；真实模型的判分质量需自行验证。模型、图片、任务及缓存预算见 [服务说明](core/server/README.md) 与 [核心接口契约](core/IMPLEMENTATION_CONTRACT.md)。

## 目录与手动添加

以下为目录结构示意；分组名、题库和拓展叶名可自行选择：

```text
quizforge_web/
  README.md
  Start-QuizForge-Web.cmd
  question-banks/
    我的题库组/
      一本题库/
        bank.json
        assets/
    未分组题库.json
  extensions/
    我的题型组/
      独立题型/
        manifest.json
        examples/bank.json
        ...
    开发题型/                         # 含 development.json 的独立叶
  skills/quizforge-bank-builder/
  core/                              # 核心源码、SDK、构建、测试与开发文档
  .state/                            # 练习、历史、编辑草稿、设置及资源
  .development/.state/               # 开发运行的隔离状态
  .trash/library/                    # 删除项目及恢复收据
  .temp/                             # 题库制作过程的临时文件
```

带图片的新题库推荐目录式 `bank.json` 与相邻 `assets/`；也支持根目录或一层分组中的普通 JSON 文件。含 `bank.json` 的目录本身就是一本题库，内部资源目录不是子分组。

题库使用稳定 `id`、`title` 和有序 `questions`。根级 `extension:{id,version}` 可作默认绑定，每题的绑定优先；可省略根绑定并逐题声明。引用必须是已安装的精确 ID／版本，物理分组名不进入绑定。题型 data、作答和判分由独立拓展定义；应用负责目录、导航、分值卡和历史。

手动新增文件后刷新目录，当前内容重新读取，其他集合下次进入时更新；相同 ID 冲突会提示，不静默覆盖。已有练习的题库优先通过应用编辑，避免手动改绑或改内容导致状态冲突。示例见 [混合题型练习](question-banks/mixed-demo/bank.json) 和 [富文本简答练习](question-banks/short-answer-demo/bank.json)。

## 用 Agent 制作题库

将 [quizforge-bank-builder 整个技能文件夹](skills/quizforge-bank-builder/) 交给 Agent，同时提供材料、产品根目录和输出位置。支持技能的应用可安装；其他应用可让 Agent 先阅读 `SKILL.md` 并按相对路径读取参考。校验需要现有 Node.js 24 与产品依赖，`--project` 指向包含 `core/` 的外层产品目录。

流程为：确认功能开关 → 分析材料与选型 → 逐轮访谈 UI 和编辑白名单 → 确认概要与实际三态原型 → 完善接口并验证小样 → 用户验收且明确许可正式生成 → 批量生成并校验、交付。

一题型、一独立拓展、一本同题型样例；相关题库放入一层题库分组，相关新拓展可放入同名拓展分组，已安装拓展可跨组复用。共享交付通过应用导出整组 `.qbank`。只确认 UI 不代表允许批量生成；生成许可也不代表允许发布拓展。正式代码更新先复制为开发版，旧正式版保留。

制作 Agent 不修改应用核心、启动脚本、设置或练习状态。全部中间产物放在技能指定的 `.temp`，最终资源放入题库／拓展。使用提示与交付规则见 [Agent 工作流](core/docs/AGENT_BANK_WORKFLOW.md) 和 [题库制作规范](skills/quizforge-bank-builder/references/bank-format.md)。

## 应用更新与兼容

当前支持 **Extension API 1.0／1.1／1.2** 与题库格式 1。旧拓展缺少 `requiresApi` 按 API 1.0 加载，旧题库缺少顶层 `formatVersion` 按格式 1 读取，不为补字段而改写；新题库建议显式声明。不支持的版本或能力在规则执行前拒绝并说明原因。

应用版本、公共富文本组件版本和拓展版本独立。已发布的同一 `id@version` 代码不覆盖或重新构建，题库保持精确绑定，旧冻结历史保留当时的页面与成绩。当前没有自动更新器、Hub 或通用迁移界面；未来主要 API 升级仍需实际实现兼容运行层。

更新前停止服务并备份整个产品目录；保留 `question-banks/`、`extensions/`、`.state/` 及需要的开发状态。`.qbank` 只传递题库和拓展，不含用户练习数据，不能用于恢复历史。不要直接覆盖已发布拓展或手动批量改绑。完整政策见 [更新兼容说明](core/docs/COMPATIBILITY.md)。
